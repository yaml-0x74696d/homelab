# Security

What the lab protects, from whom, and which file or ADR enforces each control. Current state only. Why each choice was made, and what it costs, is in the linked ADRs.

## Scope

| Data | Where it lives | Backed up by PBS |
|---|---|---|
| Photos | Immich, `photos` share on the pool | Database yes, the files no ([ADR 0013](adr/0013-pbs-file-level-backups.md)) |
| Documents and files | Paperless, Nextcloud, shares on the pool | Databases yes, the files no |
| Passwords | Vaultwarden on pod-1 (SQLite) | Yes |
| Logins | Authentik on pod-1 (Postgres) | Yes |
| Backups | PBS datastore on pve-3 | It is the backup |
| Config and secrets | this repo (public), the vault, `private.yml`, tfvars and tofu state on the controller | git, an off-site copy of the private folder ([ADR 0016](adr/0016-ansible-vault-for-secrets.md)) |

- Irreplaceable files are also kept outside the lab. The pool has no parity ([ADR 0004](adr/0004-mergerfs-instead-of-zfs.md))
- Sensor readings and metrics are low value and not covered here

## Threat model

| Threat | Main controls | What's left |
|---|---|---|
| Attacker on the internet | Only the NetBird VM is forwarded. Its dashboard and API answer the LAN only, probes get 444 and a fail2ban ban (`nixos/netbird/netbird.nix`). Certificates via DNS-01, no port 80 | The NetBird VM is the one exposed box |
| Compromised app container | Rootless, one svc user per app, `NoNewPrivileges` by default, no container socket, backends answer only `allow_from` | Root on some pod VMs can edit the DNS zone ([ADR 0034](adr/0034-tls-via-dns-01.md)) |
| Household device on the VPN | `household` group reaches edge on 443 and the DNS relay only, with a client version check ([ADR 0040](adr/0040-netbird-policy-as-code.md)) | Every route on edge:443 is reachable, a login is the only barrier |
| Stolen or lost device | Authentik with MFA for the apps, one-off short-lived setup keys, a peer leaves its group in code | Clients that are already logged in keep their offline data (Vaultwarden) |
| Supply chain (images, providers, actions) | Pinned actions and hooks, provider lock file, image health checks with rollback | Images follow tags, not digests. NixOS follows nixos-unstable nightly |
| A bad change, mine or a tool's | Same checks locally and in CI, PR to `main`, dry runs first | Whoever can merge to `main` runs code as root on the hosts within a day |

Out of scope:
- Physical access to the nodes. Their disks are not encrypted at rest
- The router, the DNS provider, the alert relay and GitHub themselves
- Denial of service from the internet

## Trust zones and network paths

The zones themselves are in [architecture.md](architecture.md#zones).

| Zone | Filtered by | Inbound |
|---|---|---|
| WAN → router | router port forwards | 443/tcp, 3478/udp and the narrow TURN relay range, to the NetBird VM only |
| NetBird VM | nftables ([`nixos/base/hardening.nix`](../nixos/base/hardening.nix)) and the PVE guest firewall ([`roles/pve_firewall`](../ansible/roles/pve_firewall/README.md)) | 443, STUN/TURN, relay range. SSH from the LAN. Egress to the LAN limited to the routing peer, DNS/HTTPS on edge, RELP |
| VPN | NetBird policies in [`tofu/netbird.tf`](../tofu/netbird.tf) | `admin`: the LAN. `household`: edge 443 and the DNS relay. Built-in all-to-all policy disabled |
| edge | nftables ([`nixos/edge/`](../nixos/edge/)) | 80/443 and 53 from the LAN (VPN arrives as pod-2), SSH from the LAN, node-exporter from Prometheus |
| Pod VMs | ufw, default deny ([`vm-preparation.yml`](../ansible/playbooks/vm-preparation.yml), [ADR 0026](adr/0026-ufw-as-guest-firewall.md)) | SSH rate-limited from the LAN, Cockpit from edge only (`cockpit_allow_from`), node-exporter from Prometheus only, each app port from its `allow_from` in `apps.yml` |
| Storage LXC | ufw | SMB from the LAN ([ADR 0017](adr/0017-smb-shares-to-docker-vms.md)) |
| Log LXC | PVE guest firewall | RELP from the known hosts only ([ADR 0022](adr/0022-central-logging-relp.md)) |
| IoT gateway LXC | PVE guest firewall and ufw, same inbound rules | MQTT from Home Assistant, exporters from Prometheus, SSH. WiFi side: MQTT, firmware HTTP, DHCP. No forwarding ([ADR 0028](adr/0028-iot-gateway-lxc.md)) |
| HAOS VM | PVE guest firewall | HA from Traefik and Homepage, admins direct ([ADR 0030](adr/0030-haos-vm-on-pve-3.md)) |
| PVE nodes | cluster firewall, policy drop for the filtered guests | Management lockdown is written but off (`pve_firewall_host_enabled: false`): SSH and the web UI answer the LAN |
| ctl-1 | ufw | Semaphore's port from its `allow_from`, SSH from the LAN ([ADR 0031](adr/0031-semaphore-on-a-single-board-computer.md)) |

- Nothing from the WAN reaches an app directly ([ADR 0003](adr/0003-netbird-instead-of-port-forwards.md))
- Every app port gets one ufw rule per source, generated by `roles/podman_app` from `apps.yml`. The port map lives once ([ADR 0007](adr/0007-group-vars-single-source-of-truth.md))
- Cockpit is reached as `pod-N.<domain>` through Traefik and forward-auth, never directly ([ADR 0014](adr/0014-authentik-as-idp.md))

## Identity and access

Apps:
- Authentik with MFA is the login for the apps ([ADR 0014](adr/0014-authentik-as-idp.md))
- OIDC for the apps that support it, NetBird and Semaphore included
- Forward-auth (`authentik` middleware in [`nixos/edge/traefik.nix`](../nixos/edge/traefik.nix)) for UIs without their own login: the Traefik dashboard, AdGuard Home, Prometheus, the Gatus status page, the Vaultwarden admin page, Excalidraw and Cockpit. Which route gets it is `middlewares:` in `apps.yml`
- Each OIDC app keeps a local admin as break-glass, except Vaultwarden, Actual Budget and linkding (SSO only)
- The PVE and PBS web UIs keep their own login

Hosts:
- SSH is key-only everywhere the repo manages sshd: `roles/vm_base` (no root login, no passwords), `roles/lxc_base` (root by key only), `nixos/base/hardening.nix` (key-only, no forwarding, modern ciphers)
- edge allows local TCP forwarding, so it can serve as a jump host for admin keys ([ADR 0032](adr/0032-edge-vm-traefik-adguard-on-nixos.md))
- The login group vars say how Ansible gets in: admin user plus sudo with `sudo_pass` from the vault on the pod VMs and ctl-1, root by key on the LXCs and the PVE nodes (`ansible/group_vars/<group>.yml`)
- Host keys are trusted on first contact (`StrictHostKeyChecking=accept-new` in [`ansible.cfg`](../ansible/ansible.cfg)). A changed key fails the run. Semaphore keeps its own `known_hosts` on its data dir (`semaphore_known_hosts`)
- NixOS VMs: `users.mutableUsers = false`, sudo for `wheel` only

Automation:
- Semaphore on ctl-1 holds the vault password and its SSH key in its encrypted key store, no tofu state ([ADR 0031](adr/0031-semaphore-on-a-single-board-computer.md))
- OpenTofu uses a PVE API token from the gitignored tfvars ([ADR 0001](adr/0001-tofu-and-cloud-init-for-vms.md)) and a NetBird service user token ([ADR 0040](adr/0040-netbird-policy-as-code.md))
- The PBS client token can add backups and restore, not prune or delete ([`roles/pbs`](../ansible/roles/pbs/README.md))
- The AI assistant works in a sandbox without SSH keys or LAN access ([ADR 0036](adr/0036-ai-assistant-in-a-sandbox.md))

## Secrets

- One Ansible Vault file, `group_vars/all/vault.yml`. The repo holds only `vault.yml.example` with empty keys ([ADR 0016](adr/0016-ansible-vault-for-secrets.md))
- Private values (domain, MACs, keys, ids) live in the gitignored `private.yml`, tfvars and private config overlays. The repo has placeholders ([`.gitignore`](../.gitignore))
- On the controller these sit in an encrypted, off-site-synced folder on secure storage
- App secrets become Podman secrets of the app's svc user and reach the container as env or a read-only file (`Secret=`). The tasks that render and compare them run with `no_log: true` (`roles/podman_app`)
- Files that hold tokens stay out of `--diff` (`diff: false`), for example `/etc/pbs.env` (mode `0600`)
- Scripts pass tokens to curl on stdin (`curl -K -`), so they don't show in `ps`. Hand steps read tokens with `read -rs` ([netbird-by-hand.md](netbird-by-hand.md))
- NixOS VMs: secrets are placed by hand under `/var/lib/secrets/`, outside the Nix store and git. AIDE watches that folder
- gitleaks runs on every commit and over the full history in CI, `detect-private-key` on every commit ([`.pre-commit-config.yaml`](../.pre-commit-config.yaml))
- CI runs with the example `private.yml` and a dummy vault password, it never sees a real secret

## Host and container hardening

Debian VMs and ctl-1 ([`roles/vm_base`](../ansible/roles/vm_base/README.md)):
- Kernel settings in `/etc/sysctl.d/90-vm-base.conf`, so they survive a reboot: SYN cookies, no ICMP redirects, `rp_filter`, ASLR, no suid core dumps, `kptr_restrict`, IPv6 off
- `rp_filter` is a dial (`vm_base_rp_filter`). It is strict everywhere except pod-2, the routing peer, which needs loose mode for the tunnel's asymmetric paths (`host_vars/pod-2.yml`)
- sshd hardened through `lineinfile` with `validate: sshd -t`
- auditd rules for `shadow`, `passwd`, `sudoers` and `sshd_config`, AppArmor, fail2ban
- unattended-upgrades for Debian-Security only, no reboot. The role fails when no security source exists ([ADR 0024](adr/0024-ansible-run-os-updates.md))

LXCs ([`roles/lxc_base`](../ansible/roles/lxc_base/README.md)):
- Unprivileged, SSH key-only, fail2ban sshd jail on the journal, the same unattended-upgrades

NixOS VMs ([`nixos/base/hardening.nix`](../nixos/base/hardening.nix), [ADR 0035](adr/0035-nixos-for-netbird-and-edge.md)):
- nftables default deny, each host opens only its own ports
- Kernel boot hardening (`slab_nomerge`, `init_on_alloc/free`, `debugfs=off`) and sysctls (ptrace scope, no unprivileged BPF, no kexec, no sysrq)
- AppArmor, auditd, fail2ban with increasing ban times
- Nightly `system.autoUpgrade` with a reboot window

Podman apps ([ADR 0021](adr/0021-podman-quadlets.md), [podman-layout.md](podman-layout.md)):
- Rootless quadlets, one svc user per app, no Docker and no container socket
- `NoNewPrivileges=true` unless an app opts out, capabilities dropped and the root filesystem read-only where `apps.yml` sets it (`drop_caps`, `read_only`)
- Config mounted read-only, data under `/srv/apps/<app>` owned by the svc user
- Every container has a health check or a stated reason not to (`healthcheck: false`), `podman auto-update` rolls back an image that fails it ([updates.md](updates.md))

## Integrity and detection

- AIDE on every Debian host and both NixOS VMs, daily, alerts with counts only ([ADR 0009](adr/0009-aide-with-manual-accept.md), [`roles/aide`](../ansible/roles/aide/README.md))
- Changes are accepted by hand after reading the diff. `update.yml` accepts on its own only if the check right before was clean
- The SHA256 of each accepted database is kept off the host, on the controllers. A mismatch alerts and stops the run
- The hashes sync between ctl-0 and ctl-1 with Syncthing, LAN only, with versions on ctl-0 ([ADR 0039](adr/0039-syncthing-between-ctl-0-and-ctl-1.md))
- login-notify pushes every SSH and PVE web login on the nodes ([`roles/login_notify`](../ansible/roles/login_notify/README.md))
- Gatus checks every route, host and PVE node, takes heartbeats from the backups and Semaphore's runs, and watches the thin pool fill through Prometheus ([ADR 0027](adr/0027-gatus-generated-from-apps-map.md))
- Prometheus and Grafana for metrics ([ADR 0041](adr/0041-grafana-dashboards-as-code.md))
- Logs go over RELP to the log LXC, 90 days ([ADR 0022](adr/0022-central-logging-relp.md))
- ntfy is the one alert path: PBS, AIDE, login-notify, image updates and Gatus ([ADR 0019](adr/0019-ntfy-single-alert-channel.md))
- Time is authenticated with NTS, so logs and TOTP agree ([ADR 0023](adr/0023-chrony-with-nts.md))

## Backup and recovery

- PBS on pve-3, file-level from each pod VM, every evening ([ADR 0013](adr/0013-pbs-file-level-backups.md), [`roles/pbs`](../ansible/roles/pbs/README.md))
- Databases are dumped first (`pg_dump`, SQLite `.backup`), then `/srv/apps` is pushed
- A failed run alerts through ntfy, a missing heartbeat through Gatus
- The token has `DatastoreBackup` on one datastore only. The three hosts share it
- No VM images: VMs are rebuilt from code and the data restored ([bootstrap.md](bootstrap.md))
- A restore was rehearsed into a throwaway VM, with counts compared ([restore-rehearsal.md](restore-rehearsal.md))
- Backups are not client-side encrypted. The datastore sits on the node's own disk

## Encryption

In transit:
- Let's Encrypt certificates through DNS-01 on every user-facing name, HTTP only redirects ([ADR 0034](adr/0034-tls-via-dns-01.md))
- Traefik to the backends is plain HTTP on the LAN, PVE, PBS and Cockpit are HTTPS with self-signed certificates
- VPN traffic is WireGuard
- SMB3 only, `smb encrypt = desired`, clients mount with `vers=3.1.1` ([ADR 0017](adr/0017-smb-shares-to-docker-vms.md))
- LAN DNS goes upstream over DoT/DoH ([`nixos/edge/adguard.nix`](../nixos/edge/adguard.nix))
- RELP and MQTT are plain text on the LAN

At rest:
- The vault is encrypted with Ansible Vault, the controller's private folder sits on encrypted secure storage
- Semaphore encrypts its key store (`semaphore_key_encryption`)
- Node disks, guest disks, the pool and the PBS datastore are not encrypted at rest today

## Supply chain and change control

- GitHub Actions pinned to commit SHAs, each job with only the token permissions it needs (`contents: read` for the checks), `persist-credentials: false`, audited by zizmor ([`.github/workflows/`](../.github/workflows/))
- pre-commit hooks pinned to commit SHAs
- OpenTofu providers: `netbirdio/netbird` pinned exactly, `bpg/proxmox` within a minor range, both checked against the hashes in `tofu/.terraform.lock.hcl`
- NixOS: `nixos/flake.lock` in git, but the VMs move to the newest nixos-unstable every night ([ADR 0035](adr/0035-nixos-for-netbird-and-edge.md))
- Images: fully qualified names (`scripts/check_wiring.py`), floating tags for apps, major tags for databases, Authentik one release series at a time ([updates.md](updates.md))
- The same checks run locally (`just check`) and in CI: lint, `apps.yml` schema, wiring, ADR and C4 checks, gitleaks ([ADR 0020](adr/0020-same-checks-locally-and-in-ci.md))
- `just render` keeps `rendered_config/` in git, so a unit change shows in the diff. `just quadlet` runs every unit through `quadlet -dryrun`
- Small fixes go to `testing`, `main` only through a PR with the `checks` job green. Commits are not signed
- Deploys start dry: `--check --diff`, `tofu plan` with targeted applies, `update.sh` builds before it switches. Stateful VMs have `prevent_destroy` ([ADR 0005](adr/0005-prevent-destroy-on-stateful-vms.md))
