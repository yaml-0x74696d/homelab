# Podman layout

Where a Podman app is described in the repo, where its files land on the host, and which unit file wins. The steps themselves are in [`roles/podman_app/README.md`](../ansible/roles/podman_app/README.md).

## Where does it go

| To change | File |
|---|---|
| host (or `hosts:` for one copy per host), uid, port, image + tag, secrets, dirs, who may reach it | `group_vars/all/apps.yml` |
| what a container mounts, publishes, checks | `apps/<app>/<container>.container.j2` |
| an app's config files | `apps/<app>/config/` (`*.j2` rendered, the rest copied) |
| a config file that isn't public | `<private_dir>/apps/<app>/config/` |
| a secret's value | `group_vars/all/vault.yml` or a template in `apps/<app>/` |
| house rules for every app (restart, health, start timeout) | `roles/podman_app/templates/10-homelab.conf.j2` |
| how map fields become unit keys | `roles/podman_app/templates/50-map.conf.j2` |
| the auto-update time, the ntfy wrapper | `roles/podman_base/defaults/main.yml` |
| `apps_root`, the svc prefix and group | `group_vars/all/app_settings.yml` |

## In the repo

```
ansible/
├── group_vars/all/apps.yml      the map: one entry per app
├── apps/<app>/
│   ├── <container>.container.j2 one per container
│   ├── <secret>.j2              a secret built from a template
│   └── config/                  mirrored to the host
├── roles/podman_base/           once per VM: podman, auto-update, the apps helper
├── roles/podman_app/            one app: user, units, config, secrets, firewall
└── playbooks/deploy-app.yml     -e app=<app>
rendered_config/example/<app>/   what the role writes, with example values
```

## On the host

```
/home/svc-<app>/.config/containers/systemd/
├── <container>.container              from apps/<app>/<container>.container.j2
├── container.d/10-homelab.conf        house rules, every container of the app
└── <container>.container.d/50-map.conf  from the apps.yml entry
/srv/apps/<app>/
├── config/                            root-owned, mounted :ro
└── <dirs>                             data, owned by svc-<app>
/etc/subuid, /etc/subgid               svc-<app>:<uid*65536>:65536
```

- One Linux user per app, rootless. `podman ps` as the admin shows nothing
- The units are generated by quadlet at `daemon-reload` into `/run/user/<uid>/systemd/generator/<container>.service`

## Which unit file wins

Weak to strong, the later file wins for single-value keys:

| # | File | Sets |
|---|---|---|
| 1 | `<container>.container` | volumes, ports, env, health |
| 2 | `container.d/10-homelab.conf` | `Notify=healthy`, restart backoff, timeouts |
| 3 | `<container>.container.d/50-map.conf` | `Image=`, `AutoUpdate=`, `User=`, caps |

- Single-value keys (`Image=`, `Notify=`, `Restart=`) are replaced by the later file, so a template can't override a house rule or a map field
- List keys (`Volume=`, `Environment=`, `AddCapability=`) add up
- A private config file beats the public one with the same path

## Looking at a live app

```
apps                                       # every app: user, status, ports
apps logs gatus --tail 50
sudo systemctl --user -M svc-gatus@ status gatus
sudo -u svc-gatus /usr/libexec/podman/quadlet -dryrun -user   # what quadlet makes of the files
```

- `-M svc-<app>@` connects to that user's systemd, needs `systemd-container`
- `-dryrun` prints the generated units, or the parse error when a unit doesn't show up

## Reviewing a change

```
just render
git diff rendered_config/
```

- Every app is rendered with the example values into `rendered_config/example/`, vault values show as `<vault:name>`
- CI fails when the folder is stale

## Conventions

- Everything an app is lives in its `apps.yml` entry and `apps/<app>/`. Nothing app-specific in the role
- Secrets go in `secrets:` (a podman secret), plain config in `config/`
- Every container has a `HealthCmd=`, or `healthcheck: false` with a comment why
- No comments at the end of a line in unit templates, systemd reads them as part of the value
- The tag is the track `AutoUpdate=registry` follows, with rollback when the new image fails its health check
- Data that must survive goes under `/srv/apps/<app>`, it's backed up by `roles/pbs`
